# UI React 工具设计说明

## 模块目标

本模块负责把静态 React/TSX UI 描述转换为 UnityBaseFramework 可使用的 UI Prefab，并用同一份布局数据提供浏览器预览和受控手动调整。

模块解决以下问题：

- 让界面层级、锚点、轴心、位置和尺寸在 React 与 Unity 间保持一致。
- 让生成界面符合框架的界面基类、资源命名和绑定收集规则。
- 允许使用者根据页面状态复杂度选择轻量界面模式或带独立状态模型的界面模式。
- 允许不同项目指定输入、输出、逻辑脚本和组件库目录。
- 允许目标项目指定生成界面统一使用的默认 TMP 字体。
- 允许目标项目指定 Prefab 模板使用的参考分辨率。
- 在没有项目专用组件 Prefab 时，为常用控件提供基础生成能力。
- 在迁移到具有自定义组件库的项目时，优先复用项目 Prefab，而不是复制或修改框架代码。
- 允许使用者在 Agent 生成页面后通过网页画布直接调整节点位置和尺寸，并继续以 TSX 作为唯一数据源。

## 职责边界

本模块负责：

- 从根面板开始解析标签中的静态字符串属性和静态层级，并安全忽略外围脚本及运行时表达式。
- 生成界面节点、基础交互控件、布局组和绑定信息。
- 创建缺失的界面逻辑类型骨架。
- 在状态模型模式下创建可继续扩展的界面、状态协调和数据模型骨架。
- 保存 Prefab，并提供 React 浏览器预览入口。
- 在已初始化的本地预览中提供画布拖动、尺寸调整、吸附、键盘微调、静态属性草稿、撤销、重做、放弃和显式写回。
- 通过受控初始化入口创建目标 ReactPreview，仅复制预览所需模板，不把发布包中的本地依赖、构建缓存或测试业务页面带入目标项目。
- 预览资源根目录必须由当前 Unity 项目显式提供；初始化入口生成项目级 `.env.local`，禁止以发布仓库或测试仓库的 `Tools/` 目录作为静默回退。
- 对生成结果执行编译、布局和场景挂载验收。

本模块不负责：

- 执行业务逻辑、界面数据状态管理或业务事件绑定。
- 运行 JSX 表达式、循环、条件渲染和远程脚本。
- 根据截图自动生成美术资源。
- 修改 UnityBaseFramework 源码或替换其界面管理流程。
- 自动决定项目的资源分包、热更新策略和正式发布配置。

## 数据与所有权

- TSX 是界面结构和布局的唯一权威数据源；手动调整必须写回 TSX，不能只保存在浏览器或生成 Prefab 中。
- 工具配置保存项目相关路径，不进入运行时状态。
- 生成 Prefab 持有 Unity 组件、层级和绑定序列化数据。
- React 预览只持有视觉预览和未保存草稿，不隐藏或修改游戏逻辑状态。
- 项目组件库 Prefab 由目标项目维护；工具只实例化和配置，不修改源 Prefab。
- 默认 TMP 字体是项目资源输入，只写入生成实例，不修改字体资产本身。

## 行为规则

- Unity 使用的属性必须写成静态字符串；动态 JSX 可以服务于浏览器交互，但不会进入生成模板。
- Prefab 根节点默认使用响应式全屏布局，填充挂载到的 UI 层；内部节点继续按各自锚点适配，预览按高度匹配规则覆盖手机、平板横竖屏、桌面宽屏和超宽屏比例。需要留边或裁剪时，使用固定参考布局模式显式保持参考分辨率。
- 武器网格、排行榜列表等重复区域使用统一布局属性表达排列规则，标题、分页按钮和其他非条目节点不参与重复项自动排列。
- 滚动组件的声明子节点属于内容容器，遮罩和滚动外壳由组件自身维护。
- 多页面界面的公共导航只维护一个共享表现层，页面状态只切换内容层。
- 图片通过 Unity 项目相对资源路径描述，React 预览与 Unity 生成共同读取同一属性。
- 组件库中存在同名 Prefab 时优先使用该 Prefab；不存在时仅对明确支持的基础控件使用内建结构。
- 自定义组件没有同名 Prefab 时必须明确报错，不静默降级为普通节点。
- 每个生成节点必须具有稳定名称。
- 可视化写回要求节点名称在当前页面中唯一；名称、组件类型和节点层级不由首版编辑器修改。
- 手动调整必须显式保存，保存前应确认源文件没有被 IDE、Agent 或其他预览窗口更新。
- 画布缩放和平移只改变编辑视口，不属于界面布局数据，也不会产生未保存状态。
- 具有唯一稳定名称且不受父级布局组控制的普通节点可以拖动和缩放；拉伸节点必须以边距语义调整。根节点和布局组子节点保持受约束状态。
- 锚点或轴心变化默认保持当前矩形，并将锚点、轴心、位置和尺寸作为一个整体撤销命令写回。
- 带绑定标识的节点必须接入框架绑定收集流程。
- 没有独立状态模型需求时优先使用轻量模式；需要长期持有业务状态、频繁响应数据变化或独立测试状态逻辑时使用状态模型模式。
- 绑定目标默认按节点组件识别；使用者显式指定绑定类型时必须严格匹配目标组件，自定义组件不得静默退化为变换组件。
- 生成界面的资源名与界面逻辑类型名保持一致，以满足框架加载约定。

## 网页设计画布与检查面板

React 预览以网页设计画布作为手动调整的主要入口。使用者可以直接选择、拖动和缩放普通节点，拖动锚点与轴心控制点，并使用锚点预设、拉伸边距、网格、父级与兄弟参考线完成响应式布局。方向键用于精确微调，右侧面板保留层级检查和精确数值输入。一次手势作为一个整体撤销命令，修改先保存在当前浏览器草稿中，只有显式保存才写回 `Generated` 页面；外部源码发生变化时必须拒绝覆盖。

画布支持独立缩放、适应窗口和空格或中键平移。视口变化不修改布局；实际节点操作必须反向换算为与 Unity 布局语义一致的静态位置和尺寸数据，不能用浏览器样式保存修正结果。

面板不直接读取或修改 Unity Prefab 序列化文件。Prefab 仍是根据 TSX 重建的输出，保存 TSX 后由使用者回到 Unity 重新生成。

## 本期非目标

- 不解析 JavaScript 变量、模板字符串、数组映射和运行时组件组合。
- 不提供节点重排、跨父级移动、多选和批量对齐分布。
- 不对布局组子节点提供自由拖动；这类布局由父级排列规则控制。
- 不自动生成正式业务逻辑。
- 不为旧格式保留额外兼容分支；输入规则变化时直接更新当前格式。
